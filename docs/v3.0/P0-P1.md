# v3.0 工程整改清单

## P0-1 首页消息发送

- `web/chat.js`：`startFromText` 不再提前占用 `state.sending`；由 `sendMessage` 单点加锁，首条消息必然进入发送流程。
- 服务端幂等：
  - `conversations.request_key` + 唯一索引；
  - `conversation_messages.request_key` + `(conversation_id,request_key)` 唯一索引；
  - `clientMessageId` 重试返回已有回复，不重复用户消息/模型调用；
  - 每对话内存锁，防止并发重复 POST 同时穿透。
- 失败重试：模型失败保存可重试错误 assistant；同 key 重试复用用户消息并重新调用。
- 测试：`tests/chat-http.test.js`（真实 HTTP 并发/重试/预算），`scripts/chat-ui-playwright.mjs`（真实浏览器）。

## P0-2 禁止空测试冒充成功

- 新对话项目：`testCommand:''`，不预置 `true`。
- 生成 `TEST_PLAN.json`、隐藏 `tests/acceptance/workbench-contract.test.mjs`、`CONTRACT.md`、`ACCEPTANCE.md`。
- 执行前：按真实仓库检测测试命令；拒绝 trivial/空测试命令。
- 执行后：要求产品测试文件（排除隐藏契约测试）、断言、可解析测试数量；退出码 0 但无测试数量 => `TEST_OUTPUT_NO_COUNT` BLOCKED。
- 依赖：`require_real_tests` + `auto_test_setup` 时按栈执行有界 npm/pnpm/yarn install；失败 `TEST_SETUP_FAILED`。
- 首轮真实通过后冻结测试文件哈希并加保护；后续修改测试需显式授权。
- 测试：`tests/v3-contract.test.js`。

## P0-3 冻结验收契约

- 基线：`CONTRACT.md`、`ACCEPTANCE.md`、`TEST_PLAN.json`、隐藏契约测试 SHA256 写入 `contract_baseline`。

- 隐藏契约测试含“契约存在/非空/验收非空”和“有独立产品测试文件”检查；Agent 不可修改。
- 测试：`tests/v3-contract.test.js`、受保护路径回归测试。

## P0-4 统一模型预算

- 表：`llm_usage`（source/source_id/provider/known/usage/cost source/budget_scope/run/task/project/conversation）。
- 迁移：从历史 attempts/audits 一次性回填，预算不重置；后续 ATTEMPT/AUDIT 触发器入账；`UPDATE attempts` 同步。
- Chat：`assertModelBudget` 预检（约 1.6k tokens），通过后真实调用；成功后 `recordModelUsage` 入账；超预算返回 409 且**不调用模型**。
- Planner：`startRun` 与 Loop `planNextTask` 前预检。
- Coding/Audit：沿用已有预检与 usage 记录，触发器进入同一账本。
- GLM：仅实际身份识别 + 实际 GLM Key/端点配置时豁免；unknown 永不豁免。
- 未修改 `MAX_TOTAL_TOKENS` / `MAX_COST_CNY`；未借用项目审计预算。

## P1 自然语言控制

- 白名单：start/status/current_task/failure/pause/resume/cost/tests/audit/delivery。
- 显式短语解析在服务端完成；模型无法直接执行命令。
- 只操作当前对话关联 project/loop；跨项目/未关联拒绝。
- actions 表持久化 `request_key` 幂等；查询只读真实 DB；start/pause/resume 调用现有 LoopManager。
- 聊天 status 不覆盖 Loop/Run 状态。
- 测试：`tests/v3-controls.test.js`、`tests/chat-http.test.js`。
