# 看见 AI：普通人操作说明

## 打开哪里

工作台地址：**http://127.0.0.1:4477**（以实际启动日志为准）。

打开后看左侧栏最下面（手机上在页面中部）的 **「看见 AI」**，有三个入口：

1. **工作台如何工作**
2. **研发实况**
3. **历史回放**

每个页面右上角都有「返回项目」，可以回到原来的项目工作台。

---

## ① 工作台如何工作：两分钟看懂

1. 点击左侧 **「工作台如何工作」**。
2. 页面会列出 11 个步骤：提出需求 → 理解目标 → 制定任务 → 写代码 → 测试 → 独立检查 → 修复循环 → 检查通过 → 保存代码 → 下一个任务 → 等待验收。
3. 点击任意步骤，会展开五个人话问题：它负责什么、接收什么、产生什么、工作台怎么知道完成、失败后谁处理。
4. 再点「技术细节（可跳过）」可以看到真实的接口/文件/状态机名称；不需要技术背景也能读上面的白话解释。
5. 页面底部有「两个关键原则」，解释为什么测试通过不能直接等于产品绝对没问题。

## ② 研发实况：现在谁在做什么

1. 点击 **「研发实况」**。
2. 右上角下拉框可以切换项目；默认是 Consumption Decision Lab。
3. 顶部六张卡直接回答：
   - 项目状态
   - 已完成任务数 / 总任务数
   - 当前 Agent（空闲时会明确显示「没有 AI 正在工作」）
   - 当前开发阶段
   - 已运行时间
   - 模型费用
4. 中间是 **AI 工作时间线**：按真实事件时间倒序排列；每行是当时发生的事。
5. 点击任意一条，会展开原始记录、运行/任务 ID 和可读数据；如果有对应运行，可点「打开这次运行」进入原来的运行详情。
6. 当前没有活动运行时，页面不会编造“正在工作”，会显示最近一次真实运行，并说明「当前没有 AI 在工作」。

## ③ 历史回放：回看消费产品怎么被开发出来

1. 点击 **「历史回放」**。
2. 页面按真实记录分五幕：
   - 第一幕：我提出了什么需求（项目目标、循环目标、冻结契约原文）
   - 第二幕：工作台制定了什么任务（计划队列、实际任务、失败/替换任务）
   - 第三幕：Claude Code 实际怎么开发（每一次 attempts、失败原因、提示词、commit）
   - 第四幕：DeepSeek Harness 怎么审计（每次审计、逐条证据、UNKNOWN/修复要求）
   - 第五幕：最终交付了什么（产品界面截图、测试、commit、源码位置、成本）
3. 用 **上一步 / 下一步** 或顶部五幕按钮切换；点「按时间线看全部事件」可以按顺序看所有真实事件。
4. 右上角可切换 **「简单讲解」/「技术详情」**：简单模式用大白话；技术模式显示 ID、token、审计原文等。
5. 点击任务可展开任务描述和验收标准；点击 commit 可读取真实 Git diff；点击审计项可看每条验收标准的证据。
6. 第五幕底部有「这次开发，AI 帮我完成了什么？」总结，严格区分 AI 自主完成、Workbench 自动恢复、外部人工介入、尚未完成/无法确认，并给出真实成本与耗时。

## 常见问题

- **为什么有时显示“未记录/无法确认”？** 因为原始数据没有入库或证据缺失；页面不会为了让故事完整而编造。
- **历史回放是视频吗？** 不是。它是从 SQLite、事件、尝试、审计、Git 和交付证据重建的页面；原始聊天消息未入库时会明确说明。
- **为什么当前 Agent 显示空闲？** 目前确实没有正在运行的 AI 任务。启动一个新运行后，时间线会显示真实事件。
- **会显示 A/B 项目吗？** 新增的实况/回放接口不返回 A/B 项目；原有项目列表行为没有改动。
