# v3.1 五类缺陷实现说明

## P0-1 暂停/恢复

- `Orchestrator.pauseRun` 改为 async：
  - `ensureControlLease` → abort controller → `waitForRunStop`（等待 `this.running` 不包含 run）；
  - 超时抛 `PAUSE_TIMEOUT`，保持 running，不显示暂停；
  - 停止后才 `updateRun({status:'paused', pause_kind})`；重复调用幂等返回。
- `LoopManager.pause` 先调用 Run pause，确认 Run 为 paused/interrupted 后才更新 Loop paused。
- `resumeRun`：
  - 已 running/queued/awaiting 幂等返回（仍先验证 Fencing）；
  - budget/wall_clock 暂停必须 `authorizeBudget`，否则 `RUN_PAUSED_BY_BUDGET`；
  - 重置中断 task（coding/testing/auditing/...）为 queued，保留 passed/commit/audit；kick 原 Run。
- `LoopManager.resume` 必须确认 Run resume 后状态为 running/queued/awaiting，才把 Loop 置 running；失败抛真实异常。
- Agent abort 时 `runTask` 不把任务标成产品失败，保留 task 检查点。
- 测试：`tests/v3-pause-resume.test.js`（fake Agent 延迟停止、pause 等待、resume 完成、2 次 Agent 调用）、`tests/v3-loop-control.test.js`、预算暂停不可自动恢复。

## P0-2 验收完成

- `contractAcceptanceStatus` 从 `project.config_json.test_plan.acceptance` 读取冻结条款；对每个 clause 要求某 PASS audit criterion+证据字符串（>=12 字符）。
- `finalizeRun` 在 awaiting_acceptance 前检查：
  - 缺失 → 自动创建 acceptance repair task，Run 重新 RUNNING；
  - 超过 maxAcceptanceRepairs（默认 2）→ Run PAUSED，pause_kind=acceptance_incomplete，绝不 awaiting。
- `LoopManager`：
  - Planner `no_task` 在存在冻结验收时 blocked；
  - max_rounds/空队列执行 `contractAcceptanceIncomplete`，缺证据 blocked；
  - `completeRound` 的 completed 分支同样检查。
- 测试：`tests/v3-acceptance.test.js`（只覆盖 A1、遗漏 A2 → 创建修复任务、再次失败 → paused/acceptance_incomplete）。

## P1-1 版本化测试基线

- `freezeTestBaseline`：
  - 每次真实通过合并现有测试 + package/lockfile/test config 哈希；
  - protected_paths 包含**精确文件路径**，不再永久锁死整个 tests/**；
  - 写入 `test_baseline_history` + `test_baseline_version`。
- `verifyTestBaseline` 在 Agent 变更后检查已冻结文件；新增测试文件允许，已有测试/runner 修改 blocked 并恢复。
- 测试：`tests/v3-contract.test.js` 新测试加入成功、version 增加、修改旧测试检测。

## P1-2 原子预算

- `model_reservations` 表；`reserveModelBudget` 使用 `BEGIN IMMEDIATE`，在事务内读 `llm_usage` + 未过期 reserved，计算剩余；唯一 request_key。
- `assertModelBudget({reserve:true})` 先预留；Chat/Planner/Coding/Audit 调用；
- 成功 `settleModelReservation`；失败/异常 release；过期自动 expired；`budgetSnapshot`/`budget()` 扣除预留。
- GLM 仅实际身份 + 实际配置豁免；DSH 项目 audit 不使用全局预留（专项预算独立）；不修改额度。
- 测试：两独立 Node 进程 6k+6k vs 10k 只能一个成功；Chat 预留结算；预算暂停不可自动恢复。

## P1-3 控制权限

- 所有控制动作 requestKey 先查 actions，验证 conversation_id/type/project/loop 归属；否则 `CONTROL_*_MISMATCH`。
- action payload 记录 projectId/loopId；幂等返回前重新校验。
- pause/resume 在 Orchestrator 内执行 Fencing lease 校验；跨项目/非 owner 拒绝。
- 模型不直接执行 shell/Git；只白名单动作。

## P1-4 崩溃恢复

- 现有 SIGKILL startRun 前/后、half-created Run、pending requestKey、auto-repair baseline 幂等、测试/契约冻结继续有效。
- pause/agent abort 保留 task 检查点；恢复只重排中断任务，不重做 passed/commit。
- 无法安全恢复时保留 paused/blocked 与现场，不伪造完成。
